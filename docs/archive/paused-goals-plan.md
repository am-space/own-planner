# Paused goals and active-goal guidance

Status: Implemented and verified. Issue: [#69](https://github.com/am-space/own-planner/issues/69).

Let users pause goals temporarily, keep reviews focused on active goals, and receive optional guidance about taking on more than five goals.

## Acceptance mapping

| Criteria | Change and evidence |
| --- | --- |
| Pause/resume in web and Telegram; terminal statuses unaffected | Append Paused to the enum; shared goal_update; Domain, Application and authenticated tool tests |
| Exclude paused goals from review, reminders and flags | Preserve active-only queries; integration test with paused linked tasks |
| Resume grants 14 days without stalled flag | Persist LastResumedAt; calculator boundary tests and persistence roundtrip |
| Relevance question includes pause | Shared weekly planning instructions; instruction/schema tests |
| Remember pause time; clear on resume | Persist PausedAt in Goal and expose it in DTO; Domain/repository tests |
| Monthly mention on first actual opening, never on reminder/skip/defer | Persist local calendar month claim in preferences, atomically claim only for live presented reviews; concurrency, timezone, restart, skipped/deferred tests |
| Mention ages and offer resuming | Application creates one sentence; render in MCP, Telegram /review and existing Settings review |
| Paused goals remain queryable; task links preserved | includeInactive, additive planner status filter; repository/tool/planner tests |
| Warn after create/resume above five; never refuse | Application DTO warning after successful write; threshold and no-repeat mutation tests |
| Warn once at review beginning above five | Atomic per-review claim and presentation field; refresh/concurrency tests |
| Existing statuses and exports preserved | Append enum numeric value, nullable columns, migration upgrade and account export tests |
| Documentation | ADR-0027, schema, AI integration, weekly review and planner references |

## Impact and order

Domain: status transitions and timestamps. Application: goal warnings, review claims and age text, stall grace, shared prompts and planner enum. Infrastructure: persistence, active-only read paths and CLI-generated AppDbContext migration. MCP: compatible descriptions/status parsing and additive DTO fields. Web/Telegram: shared service presentation, internal commands must not claim mentions. React: existing review alerts and paused planner filter only. Console/stdio: shared tools, verify builds. Tests and docs: affected layers.

Implement Domain/goal service, review persistence/application, transports and existing UI, tests, migration, docs. Reuse Goal.SetStatus, WeeklyReviewStore.UpdateAsync and the existing one-time goal-creation offer pattern. Keep tenant resolution unchanged; all claims live in the current user's database.

## Decisions, risks and exclusions

- Append Paused after Dropped to preserve stored numeric statuses. Pause only active goals; repeating a status does not reset timestamps. Existing terminal transitions remain supported.
- Use the review's frozen timezone and current local opening month (not target week) for monthly claims. Empty paused sets, expired/terminal reviews, internal command lookups and task pagination do not consume a mention. Real openings in Settings, chat and /review share the claim.
- A skipped/deferred review that was already presented has already delivered its mention; skipping/deferring without presentation does not claim it.
- Soft limit is fixed at five. Warn on creation or transition into active status, not unrelated edits. Count is advisory and may change under concurrent goal mutations.
- No automatic pause/resume, date scheduling, configurable limit, new screens or automatic task changes.
- Optional additive timestamps and warning/view fields preserve existing HTTP/MCP field names.
